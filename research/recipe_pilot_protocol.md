# Recipe review sentiment pilot protocol (fixed before model results)

Date: 2026-10-16. This is a second exploratory task to test binary text judgment transfer across source groups. It is not a paper confirmatory endpoint.

Source: [UCI Recipe Reviews and User Feedback](https://archive.ics.uci.edu/dataset/911/recipe+reviews+and+user+feedback+dataset), [DOI 10.24432/C5FG95](https://doi.org/10.24432/C5FG95), CC BY 4.0 according to UCI. Download the UCI ZIP directly and require SHA-256 `aff630962b32fb8e8fc43ba8eddf79c45e2ae70321e81dda383c95f04887b77f`. Use only review text, star rating, and recipe code; do not save names, IDs, or raw review text in result artifacts.

Define `1` as clearly favorable (4 or 5 stars) and `0` as clearly unfavorable (1 or 2 stars). Exclude unrated (`0`) and mixed (`3`) reviews, blank text, and exact normalized duplicate review text. This creates a clear binary target but does not represent every review. Text alone is the model input; recipe ID is used only for splitting and audit.

Sort unique recipe codes and shuffle with seed 42. Assign the first 60 recipes to fit, next 20 to validation, and last 20 to test. Keep every recipe in exactly one split. Within each split, sample with seed 42 to fixed counts: fit 64 favorable and 64 unfavorable; validation 160 favorable and 40 unfavorable; test 256 favorable and 64 unfavorable. Exclude cross-recipe exact normalized text duplicates before sampling. All compared methods consume the same 128 fit and 200 validation labels, with 320 additional test labels. The sampled class prevalence is 20% unfavorable in validation/test and should not be interpreted as deployment prevalence.

Run majority-positive, TF-IDF 1–2 gram logistic, length/format logistic, frozen Gemma final hidden state plus logistic, and frozen MiniLM sentence embedding plus logistic, with the settings from the SMS pilot. Fit all learned parameters on the 128 fit rows. Choose each learned method's threshold to maximize positive-class F1 on validation only, higher threshold on ties. Report test confusion counts, precision, recall, positive F1, macro F1, balanced accuracy, false-positive rate, average precision, and warm per-message inference time; report fitting/extraction cost separately. The positive class is favorable, so false-positive rate refers to unfavorable reviews incorrectly labeled favorable. Model IDs and revisions, source and split hashes, code hashes, and environment versions belong in run manifests.

Evaluate each method only once on this pilot test. Any subsequent data, threshold, or method change creates a new exploratory run. A high result would demonstrate transfer to a second text domain with unseen recipe groups; it would not establish performance on long documents, operational prevalence, or a general methods claim.
