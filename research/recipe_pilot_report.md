# Recipe-review sentiment transfer pilot (exploratory, 2026-10-16)

This pilot asks whether the same frozen-representation-plus-head workflow transfers from prompt-injection and SMS triage to a different binary task. It uses [UCI Recipe Reviews and User Feedback](https://archive.ics.uci.edu/dataset/911/recipe+reviews+and+user+feedback+dataset), DOI [10.24432/C5FG95](https://doi.org/10.24432/C5FG95), which UCI lists under CC BY 4.0. The script verifies the source ZIP SHA-256 `aff630962b32fb8e8fc43ba8eddf79c45e2ae70321e81dda383c95f04887b77f`. It does not commit raw review text, user names, or source user IDs.

The [protocol](recipe_pilot_protocol.md) was written before these model runs. It maps 1–2 stars to unfavorable (`0`), 4–5 stars to favorable (`1`), and excludes unrated/3-star reviews. Of 18,182 source rows, 15,536 unique usable reviews remain after normalized exact-text deduplication; one conflicting-label text group was removed. Seed 42 assigns 60 recipes to fit, 20 to validation, and 20 to test. The sampled sets contain 128 fit reviews (64/64), 200 validation reviews (40 unfavorable/160 favorable), and 320 test reviews (64/256). All methods use the same rows and validation-selected positive-F1 threshold; the canonical split/label/text SHA-256 is `7098133f1457fa7b9c6b365a1684127f8d5befc00cb12ff891f032687c02e51c`. All 328 fit-plus-validation labels count toward development. The test has been viewed and is exploratory, not a locked paper endpoint.

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Majority favorable | 0.444 | 0.500 | 0.889 | 1.000 | 0.800 | constant |
| TF-IDF 1–2 grams + logistic | 0.792 | 0.775 | 0.923 | 0.391 | 0.969 | 0.133 ms |
| Length/format + logistic | 0.492 | 0.523 | 0.894 | 0.953 | 0.897 | 0.056 ms |
| Frozen MiniLM + logistic | 0.681 | 0.645 | 0.915 | 0.703 | 0.985 | 3.52 ms |
| Frozen Gemma + logistic | 0.896 | 0.873 | 0.962 | 0.234 | 0.994 | 84.68 ms |
| SetFit fine-tuned MiniLM + default head (post-test extension) | 0.848 | 0.846 | 0.940 | 0.250 | 0.991 | 4.05 ms |

Macro F1 and balanced accuracy matter here because the deliberately sampled test is 80% favorable: majority-positive already obtains favorable F1 0.889 while completely missing unfavorable reviews. Gemma has 251 true favorable, 15 false favorable, 5 missed favorable, and 49 true unfavorable predictions. TF-IDF has 241/25/15/39 respectively; frozen MiniLM has 254/45/2/19. These are validation-selected operating points, not calibrated probabilities or deployment thresholds. TF-IDF is much faster on this Mac; the request figures are warm, one-message measurements, not a controlled cross-hardware benchmark. Gemma's training-feature extraction took 10.86 s versus 0.55 s for MiniLM; the linear heads took under 0.01 s. The inference figures include embedding/feature transformation and scoring, but Gemma embedding and head steps were timed separately then summed.

`research/paired_recipe.py` verifies matching split IDs, labels, and recipe groups in all six run manifests, then resamples the **20 test recipes** as paired clusters (2,000 bootstrap draws; seed 20261016). For Gemma minus TF-IDF, the observed macro-F1 difference is +0.104 with a descriptive percentile interval [0.058, 0.158]; balanced-accuracy difference is +0.098 [0.044, 0.153]. For Gemma minus frozen MiniLM, macro-F1 difference is +0.215 [0.129, 0.327] and balanced-accuracy difference is +0.229 [0.155, 0.313]. For Gemma minus SetFit, macro-F1 difference is +0.048 [-0.009, 0.099] and balanced-accuracy difference is +0.027 [-0.039, 0.085], so this split does not clearly separate those two systems. These intervals condition on one chosen training split, label budget, configuration, and threshold-selection procedure. They do not capture training-seed or task-selection uncertainty, and they are not confirmatory evidence after test inspection.

The reversal relative to the [SMS pilot](pilot_report.md)—where frozen MiniLM had the highest F1—shows that backend choice is task-dependent in these pilots. It does **not** establish that Gemma is generally superior, nor does this make Gemma the OSS default. SetFit was added under a [separate post-test protocol](recipe_setfit_extension_protocol.md) using the same 128/200 development labels and SMS training configuration; its encoder/head training took 17.28 s and one-row reload parity passed. It is a strong alternative here at much lower request latency than Gemma. This corpus has no official group-held-out split; the recipe split is ours. An aggregate-only [reviewer audit](audit_recipe_reviewers.py) found 1 reviewer shared between fit and test, 4 between validation and test, and 5 of 320 test rows written by a reviewer seen during development. No reviewer identifiers are exported. Star ratings are a noisy proxy for text sentiment. The current pilot does not test long-document inclusion/exclusion, real operational prevalence, calibration, or reviewer-disjoint generalization. Source and model pretraining contamination cannot be ruled out. The next research gate needs repeated predeclared development splits/budgets and a genuinely untouched final test before any methods-paper claim.

Run each `pilot_recipe.py --method ...` command from the repository root in the environment pinned by `requirements-research.lock.txt`, then run `python research/paired_recipe.py`. The ignored `recipe_<method>_results.json` manifests contain source/split/code fingerprints and per-row hashed IDs, group codes, scores, and predictions, but no raw text. The Gemma and MiniLM logistic heads are saved as ignored JSON artifacts. The model fingerprints do not hash weight bytes; verify model revisions and artifact compatibility before reuse.
