# SMS triage pilot (exploratory, 2026-10-16)

Question: can the frozen Gemma feature pipeline train a separate binary head on a non-security task, and is its quality/cost competitive with simpler classifiers?

Source: [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection), attributed to Almeida and Hidalgo (2011), [DOI 10.24432/C5CC84](https://doi.org/10.24432/C5CC84). UCI states CC BY 4.0. The script downloads the UCI archive directly and verifies SHA-256 `1587ea43e58e82b14ff1f5425c88e17f8496bfcdb67a583dbff9eefaf9963ce3`; the Hugging Face mirror was not used because its card lists the license as unknown. UCI supplies one 5,574-row pool, with no official train/test split or per-row source-group IDs. Raw messages are not committed by this pilot.

Protocol: strip and casefold the text for exact-group deduplication, keeping the first copy. This leaves 5,159 unique messages and no observed conflicting labels. Seed 42 samples a balanced fit set of 64 ham and 64 spam; validation has 160 ham and 40 spam; test has 320 ham and 80 spam. No normalized message crosses splits. The manifest records hashed row IDs and canonical split/label/text digest `dc74e3dd1dfcbed40c774449a03a2fc5aea2986ad8a3e7f2da683c3c4b063f81`. Total labeled development budget is 328 messages (128 fit + 200 validation); the 400 test labels are additional and were viewed during this pilot. For each method, the threshold maximizes validation F1, with the higher threshold winning ties, before test metrics are computed. The test is exploratory and cannot be reused as a confirmatory locked test.

| Method | Test precision | Recall | F1 | False-positive rate | Average precision | Warm mean per-message inference |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| TF-IDF 1–2 grams + logistic | 0.919 | 0.850 | 0.883 | 0.0188 | 0.948 | 0.132 ms |
| Message length/format + logistic | 0.764 | 0.850 | 0.805 | 0.0656 | 0.722 | 0.051 ms |
| Frozen Gemma final hidden state + logistic | 0.918 | 0.838 | 0.876 | 0.0188 | 0.952 | 74.33 ms |
| Frozen MiniLM sentence embedding + logistic | 0.948 | 0.913 | 0.930 | 0.0125 | 0.973 | 3.21 ms |
| SetFit, fine-tuned MiniLM + default head | 1.000 | 0.800 | 0.889 | 0.0000 | 0.982 | 3.25 ms |

The Gemma head and TF-IDF are close on this sample: Gemma ranks slightly better by average precision and is slightly worse at the validation-selected threshold, while costing far more per message on this Mac. Frozen MiniLM has the highest F1 and SetFit has the highest average precision; SetFit's validation-selected threshold favored zero false positives and missed 16 of 80 spam messages. The length/format baseline is strong enough to warrant source and collection-surface audits before any semantic-transfer claim. UCI does not provide per-row provenance, so a leave-one-source-out test is unavailable here. The dataset is short-message spam, not general document triage; it validates reuse of the binary workflow but does not establish performance on longer text or other domains. This is one seed and one exploratory split, with no uncertainty interval or independent replication.

Run the pilot with `python pilot_sms.py --model /path/to/gemma-3-1b-it`. The ignored `sms_pilot_results.json` contains split IDs, validation thresholds, metrics, timing, source hash, code hashes, and package versions; `sms_gemma_head.json` contains the independent task head and model/config fingerprints. The tested Python 3.12/macOS arm64 dependency versions are in `requirements.lock.txt`. Gemma embedding took 9.95 s for training messages, 15.09 s for validation, and 29.71 s for test; the head fit took about 0.003 s. Timings are warm, single-message measurements on Apple M5 MPS; the Gemma request figure sums separately measured encoding and head scoring. No model weight-byte hash is recorded. These costs are descriptive, not a hardware-independent comparison.

The two added methods use the same 128 fit and 200 validation messages, the same validation F1 threshold rule, and [the extension protocol](pilot_extension_protocol.md) written before their results. Run them with `python pilot_sms_embedding.py` and `python pilot_sms_setfit.py` in the environment from `requirements-research.lock.txt`. Both use [`sentence-transformers/all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), Apache 2.0 per its model card, pinned at revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`. MiniLM's batched training-feature extraction took 0.45 s and its head fit 0.008 s. The bounded SetFit run used 80 embedding steps, taking 9.28 s for encoder and head training. Its saved model is in the ignored `artifacts/sms_setfit/` directory. These training and request timings have different batching and measurement details, so the small MiniLM/SetFit latency difference is inconclusive.

Decision: this pilot meets the engineering goal of training and saving a second task head. It does **not** justify a methods-paper superiority claim or choosing Gemma as the public default. Frozen MiniLM is the strongest thresholded system here at much lower cost than Gemma; TF-IDF remains a useful, far cheaper baseline. SetFit may rank examples better, but its single bounded training configuration is insufficient to conclude it is worse overall. A second [recipe-group-held-out task](recipe_pilot_report.md) has now been run, with a different model ordering. That task is still short-to-medium reviews, not a long-document test. Run multiple development seeds and reserve a truly untouched final test before selecting the paper framing or public default backend.
